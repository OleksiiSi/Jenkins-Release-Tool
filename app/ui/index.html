    Release Tool help

    Release Tool builds your Jenkins jobs for one or more tickets at once and promotes the builds to your test environments. This page explains how to set up the app, configure your jobs and environments, and run builds and promotions.

    Set up Release Tool

    Before your first run, connect Release Tool to Jenkins and, optionally, to Microsoft Teams. You need to do this only once.

    Get a Jenkins API token

    Release Tool signs in to Jenkins with your username and an API token instead of your password. To create a token, do the following:

    1. In your browser, sign in to Jenkins.
    2. In the Jenkins page header, click your name.
    3. On your user page, click Security. In older Jenkins versions, click Configure instead.
    4. In the API Token section, click Add new Token.
    5. Enter a name for the token, such as Release Tool, and then click Generate.
    6. Copy the token. Jenkins shows the token only once. If you lose it, generate a new one.

    Enter your settings

    The Settings page has the following setup fields:

    Base URL
    The address of your Jenkins server, such as https://jenkins.example.com.
    Username
    The username that you sign in to Jenkins with, which might differ from the display name that Jenkins shows in its page header.
    Jenkins API token
    The token that you created in Jenkins, which Release Tool stores in Windows Credential Manager.
    Poll interval (min)
    How often, in minutes, Release Tool checks whether a build or promotion has finished.
    Max retries
    How many more times Release Tool tries a failed build or promotion, so 2 means up to three attempts in total.
    MS Teams webhook URL
    Optional: The Microsoft Teams Workflows webhook that gets a message for every finished build and promotion.

    To enter your settings, do the following:

    1. In the title bar, click Settings.
    2. Fill in the Base URL, Username, Poll interval (min), and Max retries fields.
    3. In the MS Teams webhook URL field, do one of the following:
      • To get Teams messages, replace the example address with your webhook URL.
      • If you don't use Teams, delete the example address so that the field is empty.
    4. If a token is already saved, click Change.
    5. In the Jenkins API token field, paste your token, and then click Save token.
    6. Click Save, and then in the Restart required dialog, click Restart. Release Tool restarts and starts using your new settings and token.
    7. In the title bar, check the dots next to Jenkins and Teams. A green dot means that the connection works, and a red dot means that it failed.
    Note: If you leave the MS Teams webhook URL field empty, then the Teams dot stays red. This is expected, and your runs still work.

    Configure jobs and environments

    Release Tool can build only the jobs and promote only to the environments that you add in the Jobs Config section of the Settings page. Enter every job, parameter, and promotion process name exactly as it appears in Jenkins, including uppercase and lowercase letters.

    When you first open the Settings page, the Jobs Config section contains example rows whose names start with REPLACE_WITH_. Rename each one to match Jenkins. To remove an example row, click its ✕.

    Add general parameters and environments

    Use the General section for parameters and environments that all your jobs share. Every ticket shows them once, and Release Tool applies them to every job that you select on that ticket.

    Each parameter row has the following fields:

    Parameter name
    The name of the build parameter in Jenkins, such as BRANCH.
    Type
    How you enter the value on a ticket: string for text, boolean for a checkbox, or dropdown for a list of options.
    Options
    For a dropdown parameter only, the values to choose from, separated by commas.
    unique
    Select this checkbox if every ticket in a run must use a different value, such as a branch name.

    Each environment row has the following fields:

    Environment
    The name that you see on tickets, such as QA16.
    Promotion process name
    The name of the Jenkins promotion process that promotes builds to this environment, which can differ from the environment name.

    To add a general parameter or environment, do the following:

    1. In the title bar, click Settings.
    2. In the Jobs Config section, under General, click Add parameter or Add environment.
    3. Fill in the new row.
    4. Click Save, and then click Restart.

    Add jobs

    Use the Job Specific section to add the Jenkins jobs that you want to build. A ticket shows the parameters and environments of a job only when you select that job.

    To add a job, do the following:

    1. In the title bar, click Settings.
    2. In the Jobs Config section, under Job Specific, click Add job.
    3. In the Job name field, enter the name of the Jenkins job.
    4. Optional: To add a parameter that only this job uses, in the job card, click Add parameter, and then fill in the row the same way as for a general parameter.
    5. Optional: To add an environment that only this job can be promoted to, in the job card, click Add environment, and then fill in the row.
    6. Click Save, and then click Restart.

    The unique checkbox is available only for general parameters. To remove a job, parameter, or environment, click its ✕.

    Run builds and promotions

    A ticket is one piece of work, such as a bug fix or a feature, that you want to build and promote. In one run, Release Tool builds the selected jobs of every ticket at the same time, and then promotes each successful build to the selected environments.

    Add tickets and run them

    To start a run, do the following:

    1. On the main screen, click Add ticket.
    2. In the ticket header, enter the ticket ID, such as ID-001.
    3. Under General parameters, enter a value for every parameter.
    4. Optional: Under General environments, select the environments to promote every selected job to.
    5. Under Jobs, select the jobs to build.
    6. For each selected job that has its own parameters, under Parameters, enter a value for every parameter.
    7. Optional: For each selected job that has its own environments, under Environments, select the environments to promote only that job to.
    8. Optional: To add more tickets, repeat steps 1 through 7.
    9. Click Run all.

    To collapse or expand a ticket, click its header. To remove a ticket, in its header, click ✕.

    Before the run starts, Release Tool checks the following:

    • Every ticket has at least one job selected.
    • Every parameter has a value.
    • Every parameter with the unique checkbox selected has a different value on each ticket.
    • Your API token is saved.
    • Release Tool can connect to Jenkins.

    If a check fails, then a banner lists the problems. Fix them, and then click Run all again. If the banner says that the API token isn't set, click Open settings and follow the steps in the Enter your settings section of this page.

    When the run starts, the ticket list clears and Running appears next to Run all. When every build and promotion finishes, the status changes back to Ready to run.

    Build and promotion flow

    For every selected job on every ticket, Release Tool does the following:

    1. Starts a Jenkins build with the parameter values from the ticket.
    2. Checks the build status once per poll interval until the build finishes.
    3. If the build fails, starts it again, up to the number of times in Max retries. If every attempt fails, then Release Tool sends a failure notification and doesn't promote the build.
    4. If the build succeeds, sends a success notification and promotes the build to every selected environment at the same time.
    5. Checks and retries each promotion the same way as the build, and sends a notification when the promotion succeeds or fails after all retries.

    Every notification appears as a Windows notification and, if you set a Teams webhook, as a Teams message. If you select no environments for a job, then Release Tool builds the job but doesn't promote it. If a build is already promoted to an environment, then Release Tool promotes it again and adds a warning to the log.

    Follow the log

    To watch a run, in the title bar, click Log. Each line shows the time, ticket ID, job name, build number, and stage, which is Build or Promote. For example:

    [11-10-2026 14:05:12.345] [ID-001][UI - #103][Build] SUCCESS

    Success lines are green, failure lines are red, and warning lines are yellow. To empty the log, click Clear.

    Close or exit the app

    When you close the window, Release Tool keeps running in the notification area of the Windows taskbar, so it keeps tracking your builds and promotions. To open the window again, do the following:

    1. If you don't see the Release Tool icon in the notification area, click Show hidden icons.
    2. Right-click the Release Tool icon, and then click Open.

    To close Release Tool completely, in the title bar or in the icon menu, click Exit. Release Tool then stops tracking running builds and promotions, and it doesn't start any promotions that are still waiting.
